## 实现顺序

1. **配置**：从 Lineage 节点管理独立的内部表到表草稿，管理员可新建和修改。表端点来自真实目录；仅保存配置，不创建 schedule、不访问目标数据、不修改已存在的血缘；Append / Upsert 是本系统的 PostgreSQL 写入意图，不是 Palantir 表导出模式的同义词。
2. **执行与取证**：先从一个受控试点建立只读兼容性/写入计划检查，再加入已授权的手动执行、幂等、后台检查点、提交结果和表级观测血缘。执行器不会接管现有财报或专利迁移。
3. **编排与质量**：再做真实的每日/上游事件触发、运行身份/范围、异常告警与数据检查。外部推送另走 Data Connections，不能从任意图边指定目的地址。

### 当前增量

- **Explorer 资源图标**：[官方 Source Exploration](https://www.palantir.com/docs/foundry/data-connection/source-exploration/) 的 Database Explorer 使用表格图标；[官方 PostgreSQL 连接器截图](https://www.palantir.com/assets/xrfr7uokpv1b/2zAnKGE9fiyJNTZjHoKbDw/50e7b9b68595980c81641614cec89d13/Foundry_Technical_Intro_-_Dec_2021.pdf) 第 11 页用文件夹表示 Schema 分组。Explorer 用 16×16 线框文件夹与统一的表格图标区分两类资源，不再从业务主题推断不同形状，也不以色块区分 Schema。Dataset Preview 内的 Schema 仍是列定义，不是目录里的资源节点。
- **传输预检**：管理员可对未保存的内部传输草稿运行只读目录检查，无需扫描表数据。参考 Foundry 的[表导出结构要求](https://www.palantir.com/docs/foundry/data-connection/export-overview/#special-considerations-for-table-exports)，当前严格检查同名列、类型/修饰符和目标写入约束；返回逐列问题，不把目录兼容性视为运行成功。不做自动列映射或覆盖生成列。
- **执行验收仍待实现**：区分目标的追加写入和源端增量读取；同一已提交运行重试不得重复应用，对未变化源重新发起追加必须有明确检查点策略。验证重复 Upsert 键的失败不提交数据，并将数据库合计值称为“受影响行数”。调度派发成功不等于传输提交成功。

### 受控执行试点的验收口径

- 对照 Foundry [从 Data Lineage 构建](https://www.palantir.com/docs/foundry/data-lineage/build-datasets/)与 [Build Timeline](https://www.palantir.com/docs/foundry/data-lineage/build-timeline/)定义的操作和记录。本试点只覆盖一次明确确认的本地沙箱传输与可追溯的**已提交**记录，不等于其通用 Build 系统。
- 必须默认关闭、只允许管理员，且输入和目标同时位于专用沙箱 schema。确认前显示确切的表对、写入方式和批量上限，确认绑定配置版本。结构或配置改动须重新确认；查询不到结果时重试同一请求标识，不重复写入。
- 写入与成功回执在同一个 PostgreSQL 事务内；失败不保留成功回执。不以受影响行数区分新增和更新，也不以回执记录时间冒充数据库提交时刻。没有增量源游标的追加传输不能通过新的请求重复灌入原通道。
- History 只列真实提交回执；表级观测血缘只从受影响行数大于零的回执导出。试点的观测关系不代表生产流量、全量同步、失败尝试历史、调度、变更数据捕获或外发。

### 增量追加与作业状态的验收口径

- 对照 [Foundry 表导出策略](https://www.palantir.com/docs/foundry/data-connection/export-overview/#table-export-modes)，追加是目标写入方式，增量是源读取范围，两者不能混称。我们的专用沙箱试点使用单列整数主键作为按顺序提交的水位，不是 Foundry 已提交数据集事务或 CDC。
- 同一通道第一次执行后绑定源表、目标表、模式和游标。每次最多提交 100 行；业务行、检查点、提交回执一起确认。用 201 行验收 100/100/1、无新行、同请求重试，以及失败不得推进水位或留下成功回执。键值落后、数据库更新/删除及回填不属于此模式，不能把数字主键本身当成源端按顺序提交的证明。
- 运行尝试和提交回执分开。已派发或收到请求不等于当前有运行中的工作，更不等于已提交；只有有影响行的提交回执改变 Explorer 可观测血缘。未确认结果时保留原请求 ID，不用新运行覆盖旧尝试。

### 接入现有自动化调度的验收口径

- 复用现有 Automation Center 的 Schedules 和 Celery 的共同分钟调度入口；不新增产品级调度模块。Lineage 负责绑定传输草稿和授权开启，Automation 展示已绑定的计划，Explorer 仍只展示实际提交的数据流。参考 [Foundry Schedules](https://www.palantir.com/docs/foundry/data-integration/schedules/) 对调度启动与构建结果的区分。
- 首期仅允许本地专用沙箱中的每日 Upsert，必须明确绑定并默认关闭；内部日程按 UTC，Automation 同时显示浏览器本地时钟。暂停、重新开启、草稿版本变化和超出五分钟窗口不得补跑旧任务。
- 同一计划代次与 UTC 时间槽只允许一个持久作业。应验证重复派发、消息未确认和工作进程故障，按同一记录恢复，不把消息派发当作写入成功。实际提交必须有数据库回执，重试不能重复写入。
- 仍未覆盖跨库、生产、批量入站、上游事件触发和任何对外发布。

### 数据源发现的验收口径

- 对照 [Data Connection Source Exploration](https://www.palantir.com/docs/foundry/data-connection/source-exploration/) 的数据源树、搜索和元数据面板。Explore source 放在现有 Data Connections 已保存连接内，不另建导航。
- 只用已保存的 PostgreSQL 连接和其现有凭证。管理员发起请求，但结果仍受数据源数据库账号的 USAGE / SELECT 权限限制；不显示系统 schema 或不可读的关系。按页读取目录，列通过元数据提供类型、可空性和主键，不读源表的行。
- 在列详情中显式加载普通表的一跳原生外键，可查看引用和被引用两个方向；复合列按数据库定义顺序显示。所用系统目录字段要求 PostgreSQL 11 或更新版本；验收使用 17。分区表及继承树不在范围内。只显示 PostgreSQL 已验证的约束，两个端点及每一对参与列均须可见；先按权限过滤、再合并完全相同的引用并截断，每个方向最多显示 12 条。请求绑定已保存连接的确切版本，版本过期时不连接新地址，要求重新加载。结果不缓存，下次加载重新检查权限。
- 此处只读取数据库系统目录，不读取样本行，不展开关系图，不根据列名推断引用，也不把结构引用当成真实传输血缘。其他连接器、外部样本预览和网络策略配置未由该功能覆盖；目录可读不代表有权限写入目标。

### 已保存连接的能力状态

- [配置 Source](https://www.palantir.com/docs/foundry/data-connection/set-up-source/)将源配置、验证连通性和建立 Sync 分开；[Source Exploration](https://www.palantir.com/docs/foundry/data-connection/source-exploration/)也按源类型区分可探索的内容。本系统在已保存连接详情中显示 Test、PostgreSQL 目录、普通托管快照、已提交批次及已审核主键区间五项状态，不另建导航或在展开每个连接时另发请求。
- 状态取自已保存元数据、服务端驱动和试点开关；托管同步另核对本地地址及适用的源身份审核状态。列表不解密凭证、不连接源、不读取业务行，也不发起同步。暂停继续阻止相关操作；停用源身份试点不会自动把之前留有审核记录的源降级成旧快照。非 PostgreSQL 只展示已有连接测试的资格，不暗示支持目录或同步。
- “可尝试”不等于已连通、发现了目标表或已经得到运行授权。实际操作仍按现有规则检查凭证、权限、源身份与计划。本状态不替代运行回执，也不表示已部署或与 Foundry 完全等价。

### Managed batch sync 的试点边界

- 对照 Foundry [设置同步](https://www.palantir.com/docs/foundry/data-connection/set-up-sync/) 和 [JDBC 同步优化](https://www.palantir.com/docs/foundry/data-connection/optimize-jdbc-syncs/)。先从现有 Data Connections 选择已保存的 PostgreSQL 表，明确字段和主键映射，保存版本，再确认向已存在的本地沙箱表写入。
- 首期是有上限的快照 Upsert：只读源端已观测快照，不清空目标，不删除源端缺少的旧目标行，也不把整数主键或更新时间冒充源提交游标。源和目标是两个事务边界，回执仅证明目标接收了一次独立观测到的源快照。
- 同一物理目标上的重叠请求必须在打开源快照之前串行化或拒绝；用两个不同计划或请求 ID 的旧值/新值竞争测试，防止后提交的旧快照覆盖新值。相同请求重试应直接读取目标回执，不重读源；失败或超出 100 行、单行 8 KiB 的上限不得留下部分写入或成功回执。
- 试点默认关闭，只在显式本地配置允许、环回 PostgreSQL 源和专用目标 schema 中启用；不连接生产或外部主机。调度、源变更日志、外部导出和下游权限规则不在本次试点中。

### Batch Sync 执行记录与安全重试

- 记录每次执行尝试，区分已记录、已提交、回放既有回执、拒绝、可重试及结果不明。没有结束时间的尝试只表示请求曾被记录，不保证任务仍在运行。[Foundry Job Tracker](https://www.palantir.com/docs/foundry/data-connection/troubleshooting/#job-tracker)
- 相同请求 ID 绑定同一个已保存版本。若存在提交回执，重试直接返回原回执，不重新读取源或写目标；目标数据、回执与成功执行状态必须同事务提交。可确认没有写入时才显示已拒绝或可重试；最终提交未确认时显示结果不明。
- 验收覆盖目标繁忙、版本改变、路由或范围超限、源临时不可用及响应丢失；执行尝试与成功回执分别展示，不从没有成功回执的尝试生成血缘。仅限受控沙箱手工运行，不自动重试或另建调度器。

### 批量同步接入现有 Schedules 的验收口径

- 对照 [Set up a batch sync](https://www.palantir.com/docs/foundry/data-connection/set-up-sync/)：保留从已保存源管理或手动运行同步的入口，由现有 Automation Center 的 Schedules 观察定时作业。此试点不创建通用 Foundry Dataset 或构建系统，仅支持已经配置好的环回 PostgreSQL 工单和既有本地沙箱表。
- 每日按 UTC 派发并同时显示浏览器本地时间。初始默认关闭；启用时需确认源、目标、写入方式和每日时刻，并绑定审核过的同步计划和连接版本。暂停、旧版本、授权失效及超出时间窗口的派发不能开始新写入，不做历史补跑。
- 同一日程代次及 UTC 时间槽至多一个持久作业，同一作业重投使用原请求标识。派发记录、执行尝试及目标提交回执各自展示；验证竞争、同任务重复投递和重试的结果必须取自实际隔离数据库。目标写入、提交回执和作业成功状态需同事务落库。
- 不覆盖生产开关、任意周期或上游事件触发、CDC、外发或自动创建目标表。通过真实 PostgreSQL 与模拟消息通道的测试不等于验证了生产部署。
- 运行前提：启用仅限 API 与 worker 共享同一个已验证的环回网络命名空间、同一目标注册库及凭证密钥的隔离沙箱。标准分容器环境的 `127.0.0.1` 各自独立；不把 API 手动运行通过当作 worker 源端身份已经验证，不在默认部署启用。下文源身份试点在手工和 worker 各自的源事务内校验标记；仍不开放非环回源或默认分容器部署。

### 受控 PostgreSQL 表导出的验收口径

- 对照 [Foundry Table exports](https://www.palantir.com/docs/foundry/data-connection/export-overview/#table-exports)：从 Data Connections 查看已批准的目的端、列映射与运行历史。[Outbound webhooks](https://www.palantir.com/docs/foundry/data-connection/webhooks-overview/) 是另一种产品能力；Published API 被动响应读取，不是主动发送。本轮不以 Webhook 或 Kafka 派发模拟表导出。
- 首期只允许在显式开启的隔离环境中，由管理员向预置、经过身份验证的环回 PostgreSQL 发送专用合成源表。目标主机、库、表、列及凭证由部署批准，不能从界面填写任意地址、表名或 SQL。固定映射 `id → id`、`caption → caption`；有界快照 Upsert，不删除接收端独有的行，不实现镜像、截断或增量。
- 发送方记录计划版本、原请求 ID、执行尝试和受控载荷摘要，不持久化导出原文或凭证。目标业务行和目标自己的回执同事务提交，两个数据库之间不承诺原子性。失去确认后仍用原 ID 先核对接收回执；若接收端没有回执且当前源内容已变，不得用原 ID 发送不同快照。没有匹配接收回执则不能显示已提交或生成已观测的外发血缘。
- 验收要覆盖权限和开关、目标身份不匹配、超限无部分写入、不同请求的并发、重复/丢失回应后的原请求核对、目标特有行保留，以及接收端提交与界面尝试记录分开展示。生产目标、跨网络、其他格式和上游事件触发不在试点范围。

### 外发血缘证据

- 按 [Explore data lineage](https://www.palantir.com/docs/foundry/data-lineage/explore-lineage/) 的资源上下文检查关系。在精确源表的 Lineage 和 Explorer Evidence 里展示受控接收端标签；不在其它表或全局图里误挂固定沙箱通道。图上的声明与观察必须用不同状态，目的节点不暴露主机、端口、数据库、标记或凭证。
- 不在页面查询期间连接接收端。仅使用发送方已核验并保存的接收回执。当前已审核版本及同一目的绑定中有影响行的回执才产生当前观测边；改版后仍保留带原审核时间的历史，不把旧回执归给新版本。零行只有审计记录；尝试、拒绝、结果未知与草稿都不生成观测流。
- 此处只覆盖固定沙箱源和管理员核对场景，不是跨系统生产血缘、列级影响分析或对外数据治理的整项验收。

### 上游提交触发的验收口径

- 对照 [Data updated 触发](https://www.palantir.com/docs/foundry/building-pipelines/triggers-reference/)：复用 Automation Center + 现有分钟调度。第一阶段仅支持管理员显式绑定一条沙箱依赖，手动 Upsert 的目标表就是下游 Upsert 的源表。开启时核对两个计划版本及物理表身份；不得自触发或级联，此阶段不支持多父节点 AND/OR 或把 UTC 时刻与事件组合。
- 上游目标数据、自己的回执和可用事件同事务提交。仅正数受影响行产生事件，不把已派发、回滚、失败、零行或同请求回放当成新事件。受影响行数不等于内容发生变化。开启/重新开启只消费此后提交的合格事件，不扫源业务行寻找变化或用 CDC 偏移代替提交。
- 下游按绑定代次和原上游事件去重，重复派发使用同一作业标识。暂停、撤权、计划改版、表变更或过期时不能开始新写入；下游成功需要自己的提交回执。下游触发时读取实际执行时可见的已提交表数据，不把上游回执当成可回放的不可变源快照。

### 外发授权与撤销的验收口径

- 对照 [Foundry Exportable markings](https://www.palantir.com/docs/foundry/data-connection/export-overview/) 和[访问控制传播](https://www.palantir.com/docs/foundry/security/access-control-propagation/)。导出配置、对象/字段可读或普通管理员身份，不代表已经授权外发。只有经单独审核的固定合成资产、明确的字段与类型映射、批准的接收绑定和 `sandbox-synthetic` 标记可执行，默认拒绝。
- 授权绑定审核版本、当前部署范围及授权代次。版本或目标变更、撤销、未分类或不匹配均拒绝在源表或接收端进行新的 I/O；结果不明的重试也受同一授权约束。撤销与已获准执行串行化，成功撤销不能撤回此前已经提交的数据。
- 旧回执与授权审计不被修改；普通受控历史和 Lineage 不再展示失效授权的细节或观测边。不得以调试日志、快照、连接主机或凭证泄漏代替审计。此试点不宣称覆盖通用资产标记继承或生产治理。

### 多上游组合条件的验收口径

- 对照 [Foundry 触发类型](https://www.palantir.com/docs/foundry/building-pipelines/triggers-reference/)：本轮只覆盖同一层的 AND／OR，1–3 个明确审核的沙箱手动 Upsert 上游，且它们写入同一个下游源表。不包含嵌套表达式、跨资产编排、UTC 与事件组合。
- AND 等到每个已审核上游都至少有一条未消费的正数提交事件，再各取一条作为一个固定集合；先到的事件不能因等待另一条同组事件而被静默丢弃。OR 每次只取一个上游的下一条合格事件。一个事件在同一下游和代次内只能进入一个作业；并发分配、发布失败和 worker 重投不会重复消费或重复提交。
- 每条父回执和下游提交回执分开显示。暂停、换父节点、换 AND/OR 或版本改动需启用新代次；旧作业不能重新使用当前授权执行。迁移前的单上游配置和已提交作业保留原有回执关系。当前仍是从执行时可见的已提交表读取，不等同于固定历史快照。

### 资产写入新鲜度的验收口径

- 对照 [Foundry Checks reference](https://www.palantir.com/docs/foundry/health-checks/checks-reference/) 的更新时间类检查。本轮配置的是「距上次已确认写入」，不是业务字段、源端或生产数据的通用新鲜度。仅在精确内部沙箱目标及绑定计划的审核版本下，由管理员保存阈值和启停。
- 仅以当前物理目标的正数、已提交回执作为有效观测。没有可信回执、旧版本、表被重建或评估已滞后时显示未知，不能将旧回执补认成新物理表的更新。零行、派发、拒绝和结果未知不会刷新时间。界面区分回执记录时间、检查时间和阈值。
- 复用现有 Automation 分钟任务在后台读取有界目录与索引内的回执，不扫描源或目标业务数据，不联系外部系统。验证进入超期、恢复、暂停、并发去重和最近状态变更；本轮不发送外部告警。

### 结构基线与物理大小的验收口径

- 参考 [Foundry Schema checks](https://www.palantir.com/docs/foundry/health-checks/checks-reference/#schema-checks) 的有序精确结构比较。在同一沙箱检查中独立配置结构规则：管理员明确确认当前版本后才保存基线，比较有序列名、PostgreSQL 类型与修饰符、可空性和主键顺序。调整其他阈值不得顺手接纳结构漂移；重新采集必须再次显示并校验被确认的目录版本。
- 大小规则针对 PostgreSQL 主表数据文件字节数（不含索引及 TOAST），可设置区间。它不代表逻辑行数，也不和 Foundry 的通用数据集规模规则视为等价。后台只读取有界目录与存储元数据，不扫描业务行，不向外部发送告警。
- 新鲜度、结构、大小分别展示正常、失败或未知及各自评估时间。停用、失去可信物理绑定、评估过期和目录不可核对，不得显示正常。验证精确结构漂移、显式重设、实际堆文件大小越界、并发记录去重，并保持原有写入新鲜度。

### 站内质量告警的验收口径

- 保留现有 Automation 分钟评估，不增加派发或外部通知。当前有效的写入超期、已确认结构漂移和主堆越界才开启告警；同一资产、规则和持续故障不能在并发或重复评估中创建第二条。
- 人工确认只记录已查看，不会关闭仍在发生的告警。检查未知、停滞或找不到可信证据，不代表恢复。只有同一有效规则重新确认通过才记为恢复；暂停或改版明确记为已替代，不伪造恢复。恢复后的新故障有新的告警 ID。
- 管理员从精确沙箱资产的 Evidence 查看当前告警与有限历史。验收权限、版本、重复操作和确认过程中已恢复的竞态，保留可核对的时间和状态，不扫描业务行，不泄露连接或业务数据。

### 资产运行时间线的验收口径

- 参考 [Foundry Build Timeline](https://www.palantir.com/docs/foundry/data-lineage/build-timeline/)。管理员在现有 Explorer Evidence 查看精确沙箱目标表，分页区分已提交回执、可归属的执行尝试和相关触发详情。没有回执的尝试不报提交或行数；零行回执保留但不证明数据流动。
- 版本及目标归属从写入或请求接受时的不可变记录取得。改计划、重建表或重新使用相同名称不迁移历史；缺少物理身份的旧回执只作历史，旧失败记录不能引用现版本反推归属。UTC 槽、上游父回执集合仅从真实关联查出，不能从 ID 格式或当前计划触发配置推断。
- 验收同时间排序的有界翻页、跨表隔离、空回执与结果未知，以及物理替换后的证据标识。未确认归属的作业仍在 Automation 各自历史中，不伪造资产归属。

### 合成 CDC 回放的验收口径

- 参考 [Foundry Change data capture](https://www.palantir.com/docs/foundry/data-integration/change-data-capture/) 的变化事件与增量应用。此轮只在明确开启的本地合成沙箱，用固定审核的 PostgreSQL 日志回放已提交 after-image Upsert，不启用真实连接器、外部推送、删除或现有 Kafka、Debezium 及 WAL 配置。
- 夹具生产者在源变更同事务分配连续序号、记录事件及源端最高位点，回滚不遗留可见序号。应用只读有界连续前缀（50 条、64 KiB），目标行、应用检查点和提交回执同事务；空批、缺号、未经确认的配置或表替换不推进。源端最高位点可与目标已提交检查点不同。
- 重放原请求先读取原回执，不读源日志、不再次应用。目标写后回执失败一并回滚；提交确认丢失用原请求恢复。按影响的目标行与已应用事件范围分别表示结果，不把读取或投递当作目标提交。全程不接触生产。

### 已提交合成数据版本与比较的验收口径

- 参考 [Foundry Dataset Preview Time Travel](https://www.palantir.com/docs/foundry/dataset-preview/time-travel/)。仅对明确开启的合成 CDC 目标采集有界版本，不将生产表或历史旧回执纳入，也不从当前表补造历史。
- 新的目标行、应用检查点、回执与有界版本快照同事务。启用版本记录后，不能在限额内完成快照或写入失败时整批回滚。关闭时原 CDC 回放语义不变；同请求重放返回原回执，不另造版本。版本用不可变回执和检查点标注。
- 查看和比较均只读已保存快照。新增、更新、删除从两个真实版本的键和值比较得出，不是恢复或删除操作。键用十进制字符串保证 bigint 无损；页面不会提供当前数据变更、恢复、任意表采集或生产历史能力。

### 可视化转换试算与配置版本的验收口径

- 参考 [Foundry Pipeline Builder workflow](https://www.palantir.com/docs/foundry/pipeline-builder/overview/#workflow) 对转换、预览和输出的区分。Ontology Transformations 保留原 Handler，新增明确开启的本地合成 Builder 路径。起点只能选择一条真实保存的 CDC 版本，配置受支持的类型化筛选、字段和列顺序，显示经过真实计算的预览。无任意 SQL、代码、外部连接或输出写入。
- 预览和保存配置分别操作；保存产生不可变配置版本并引用精确输入版本，不产生数据集提交回执。过期基线不能覆盖最新配置，已保存版本的输入、规则及结果可重查而不读取实时表。
- 验收空输出、有匹配和无匹配、bigint 字符串而非 JS 数值、精确列顺序和内容、旧输入版本稳定、权限与环境门槛及并发保存。此轮无实际发布数据、任意拓扑或生产转换。

### Builder 已提交输出的验收口径

- Builder 试算、配置保存和数据提交分别显示。只有本地合成范围、另行显式启用、管理员确认且绑定当前已审核配置版本及指纹，才写入专用的不可变输出存储。输入来自已保存快照，不读写实时业务表，不接受任意输出位置。
- 结果行和输出回执同事务，读取从存储重现已提交版本；失败不得留下部分行或成功回执。以原请求重放返回同一结果，不再试算或新增版本。零行允许成为真实空结果，但不是写入行或观测数据流。
- 验收普通预览/保存无输出、取消无提交、并发去重、失去回执后的原请求恢复、旧版本可读与失效审核拒绝新提交。此轮不部署、不恢复生产数据，也不宣称任意 Pipeline 发布。

### 有索引保护的 Explorer 预览验收口径

- 普通 `LIMIT` 只限制返回行数，不能证明不会全表扫描。在明确开启的本地合成表中，先校验精确表结构与主键索引，按原绑定参数用 [PostgreSQL EXPLAIN](https://www.postgresql.org/docs/current/using-explain.html) 检查计划，不使用 `ANALYZE`。仅有界行数、主键精确或范围筛选、固定主键顺序以及直接受支持的索引扫描才执行，不允许残余过滤、全表扫描、排序或其他计划回退。
- 仅检查计划不会查询业务行；没有合格计划、索引被移除、超时或筛选方式不受支持时显示阻断原因，不展示原始计划中的用户参数。执行与预检使用同一 SQL 及参数，并在带短超时的同一只读事务内稳定目录。
- 验收 10 万级合成行的索引路径、非支持条件无行查询、普通路由不能绕过固定的合成预览、其他表和权限不变。此轮不对生产 Explorer 启用全局保护，也不声明 EXPLAIN 是实际性能测量。

### 合成资产标记继承的验收口径

- 合成版本封存基础标记；Builder 的配置可在审核时添加更严格的标记，不能移除输入保护。由该配置提交的输出封存实际继承后的标记，筛选、列映射甚至零行结果都不能降低保护级别。保存配置和提交结果仍是不同操作。
- 本地显式授权以当前已认证的人和精确合成范围为准，不能从客户端声明、管理员身份或别的导出授权推断标记许可。开启时，无明确标记的旧记录和不受支持的记录不得自动接纳；关闭开关也不会把已保护的版本公开。
- 验收列表、详情、双版本比较、试算和重放都在读保护行或执行前校验授权，撤销后旧请求也不能重新取回。此轮只覆盖固定本地合成 CDC 与 Builder 派生关系，外部导出和生产授权不变。

### 已保存 PostgreSQL 源身份的验收口径

- 连通性只证明能够登录，不能证明手工操作与调度 worker 连接的是同一个源。默认关闭的本地合成试点为已保存连接提供独立的只读身份验证，必须匹配部署端预置标记和当前连接版本。验证不读取业务行；界面和 API 不展示标记、凭证或内部指纹。
- 审核绑定具体源表；新执行在同一个只读源事务内验证身份、锁定并复核所审核的物理表，再读取一批数据。凭证或连接改版、同结构错库、标记不可读或物理表已替换时必须失败；不得写目标、推进位置或生成成功回执。已经提交的原请求按原回执恢复，不因此重读业务行。
- 在隔离夹具中，由源管理员为 `batch_sync_identity.source_identity`（唯一列 `marker uuid PRIMARY KEY`）预置一条记录。保存的连接账号只有 schema 的 USAGE 和标记表的 SELECT，不能拥有或改写该表。由部署端分别为 API 和 worker 注入同一预期值；先验证已保存的连接，再审核映射，不把通用“测试连接”当作审核。
- 已验证连接既有的保护不会随凭证轮换、验证失败或关闭试点移除。试点关闭时，该连接不能新建旧模式计划，也不能启动已有计划；仅已提交的原请求可返回既有回执。含此类记录的数据库不允许降级并删除保护。
- 这是独立配置的合成源标记校验，不是 TLS 身份验证，也不能防御具备源管理权限的人克隆标记。验收覆盖手工与现有自动化调度路径，无生产连接或部署。

### 已提交批次增量同步的验收口径

- 旧的快照 Upsert 保持默认。默认关闭的增量模式只接受已通过身份审核的固定合成 PostgreSQL 流和专用目标；仍使用现有的手工入口和 Automation 调度。产品按源端事务实际发布的批次序号读取，每次至多应用一个完整批次。实体主键仅用于合并行，不得当作提交游标；未出现的目标行不会删除。
- 隔离源夹具使用仓库根目录的 `tools/fixtures/committed_batch_source.sql`，由源管理员执行预置；应用保存的连接身份必须为只读。目标使用独立的 `ts_batch_sync_sandbox.committed_batch_fixture(id bigint PRIMARY KEY, value text NOT NULL)`，不自动创建或重绑目标。
- 区分源端已发布位置、目标端已应用位置和无新批次。目标行、已应用位置、该次请求回执和调度执行结果必须同事务；相同原请求直接恢复已记结果，不重读源。游标不能因重审而归零；缺批、回退、身份或物理表改变不等于“无新数据”。无新批次不生成写入或流动证据。
- 实测源端事务竞争与回滚、跨手工与定时的连续应用、并发和重试、目标失败原子回滚、新数据为零、旧快照兼容。仅用于隔离合成夹具，不包括任意业务表、真实捕获连接器、生产调度或部署。

### 已提交批次的资产血缘与运行时间线

- 对照 [Explore data lineage](https://www.palantir.com/docs/foundry/data-lineage/explore-lineage/) 和 [View build timeline](https://www.palantir.com/docs/foundry/data-lineage/build-timeline/)。在现有 Ontology Lineage 选择受控目标资产，查看已审核上游和有时限的运行证据；Data Connections 的同步结果跳到同一详情，不增加独立设置入口。
- 只有绑定的物理目标仍匹配并存在真实正数提交时才呈现已观察数据流。草稿、已审核但未提交、失败和无新数据都不画成已观察数据流。目标被替换、重写或移除时，旧回执保留为历史，不归到新对象。耗时只由实际已记录的起止时间得出。
- 查询只读取应用中的不可变回执、可精确归因的运行记录和受限目标目录，不连接源，也不读取目标业务行。窗口和分页有界；旧的未归因记录不按最新草稿猜测归属。入口只面向启用试点的本地管理员，目标仍不能从普通 Explorer、公开链接或通用 SQL 获取。

### 三来源括号式提交触发的验收口径

- 对照 [Compound trigger](https://www.palantir.com/docs/foundry/building-pipelines/triggers-reference/#compound-trigger)。继续使用 Lineage 的上游条件和现有 Automation：三个不同的已审核上游允许选两个组成反向 AND/OR 子组，支持 `(A AND B) OR C` 和 `A AND (B OR C)`。原单条件或平面规则不变；这轮不混合时间或其他事件类型。
- 派发必须有完整且真实的正数提交回执，列出本次实际满足条件的事件。只消耗选中的事件，其他分支等待；不能用同一个共享事件满足两次，单条等待事件不挤占有限的就绪队列。每个任务保存当时审核的整个规则与选中证据，运行前复核全部三个上游、配置代次和触发窗口，不将派发当作目标写入。
- 验收两种括号组合、同一时间的确定性、过期与并发重复、未选上游失效、旧规则和历史兼容。仍限默认关闭的隔离试点，不启动生产调度。

### Explorer 已采集表统计的验收口径

- 在同一资产的 Evidence 查看后台采集的 PostgreSQL 规划器行数估计。复用现有定期资产检查，只对本地已审核的物理沙箱资产读取有界目录和分析时间。打开页面读取已保存的观察，不触发采集，不读取业务行、不运行 `COUNT(*)` 或 `ANALYZE`，不读列值或直方图。
- 分开记录采集时间和数据库报告的最近分析时间。估计为零不代表表为空；未报告的估计不是零。目标重写、配置失效、统计重置或采集过期时，不把旧值伪装成当前观察；本地管理员也不能从该入口读取未审核、隐藏或不支持的资产。
- 这是表级规划器元数据，不等同于 [Foundry Dataset Preview](https://www.palantir.com/docs/foundry/dataset-preview/overview/) 的列分布统计。估计语义见 [PostgreSQL pg_class](https://www.postgresql.org/docs/current/catalog-pg-class.html) 与 [Cumulative Statistics](https://www.postgresql.org/docs/current/monitoring-stats.html)。仅隔离验收，默认关闭。

### 独立的本地合成推送收件箱验收口径

- 参考 [Foundry 推送入站](https://www.palantir.com/docs/foundry/data-connection/push-based-ingestion/) 的生产者身份与固定数据结构。此试点不模拟 Foundry OAuth/API 兼容性：入站只在另行启动的数值环回监听器（`python -m app.web.push_inbox_ingress`）注册，默认关闭，普通 Web 服务不注册生产者入口，不接 Kafka、CDC 或目标写入。
- 生产者使用部署端预置公钥验证固定路径、请求标识、有限时间和正文；管理员浏览会话不等于生产者许可。对固定合成记录流式限制请求大小，拒绝非预期字段、无效签名、重放内容被替换、超速或容量已满。规范化记录、序号和接收回执原子保存；通过验签的同原请求重试只返回原回执。
- Connections 展示授权接收摘要，不展示正文、公钥材料、签名或数据库标记。接收回执不是消费位点、目标提交、数据流血缘或已应用记录。验收需涵盖正常 Web 服务隔离、错身份、并发重试、真实回滚和轮换；仅合成隔离环境，无生产部署。

- 迁移 `a9fcc74e95b1` 安装控制。暂停时，仍运行的旧版入站进程若按原协议在同一事务新增回执和更新计数，将整笔回滚，不改动回执表的物理审核条件。已经用过控制的库拒绝降级移除保护。

### 已接收推送记录的专用目标手工应用

- 入站许可不自动授予目标写入。另行启用默认关闭的本地试点，由管理员审核固定、已预置的合成目标，再明确确认要处理的已接收范围。目标按接收序号保留事件；同一实体的两次接收也不是一条事件。未获审核的新到记录不包含在当次应用。
- 接收序号、应用位置和验收回执是独立事实；应用时校验连续记录与已审核物理身份，并在同一个数据库事务写目标、推进应用位置、保存独立回执。失败三者同退；原请求可取回原结果。无新数据不是成功写入，不能提高应用位置。任一物理表身份改变不得重绑并从零开始。
- 不提供通用目标查询、公开链接、任意写入、自动调度或 CDC 消费。仅在隔离数据库用实际拒绝、并发、回滚及浏览器结果验收。

### 每日 UTC 同步结果健康检查

- 参考 [Foundry Sync status](https://www.palantir.com/docs/foundry/health-checks/checks-reference/#sync-status)。在现有资产 Evidence 的 Quality 中审核绑定已启用的每日 UTC 调度、相同计划版本与目标表，只检查审核之后该代次最近时段的持久作业结果。使用现有后台资产检查，不启动同步、不查询业务行、不发外部通知。
- 真实正数提交必须有匹配目标和调度任务的回执。明确失败必须来自本次已归因的目标写入尝试与已确认回滚，不能从错误消息或旧拒绝推算。无任务、尚未完成、过期、提交结果未确认、无写入或身份变更分别保留为未知状态或说明，不误报成功或失败。
- 明确失败才产生独立站内告警；确认已读不算恢复。只有同审核范围内后来可证实的正数提交能恢复；暂停、重新审核或目标替换不把历史告警标成恢复。试点默认关闭，仅验收隔离本地资产。

### Builder 双输入按 ID 匹配

- 参考 [Foundry Builder Join](https://www.palantir.com/docs/foundry/pb-functions-transform/joinV2/) 中的 Semi join。本地 Builder 可选择同一合成流的两个不同封存版本，以精确有符号 bigint ID 为条件，只保留右侧也存在的左侧行。值和顺序仍来自左侧，再执行已有筛选和字段映射；不提供任意 SQL、其它连接类型或生产版本。
- 先审核两个输入的身份与权限，再读任何数据。审核版本、结果和回执保存双输入绑定；输出继承两个输入和当前审核配置中的最严格标记，即使没有匹配行。撤回权限时，历史详情和原请求回执也按当前权限检查。
- 预览和明确提交使用相同计算；已提交结果保留原版本，不随之后的数据变化或关闭试点自动改算。旧单输入 Builder 与 Handler 不变。验收包含重放、真实故障、大小预算和兼容性；仅隔离环境，默认关闭。

### 第二个预置 PostgreSQL 表导出接收端

- 参考 [Foundry Table exports](https://www.palantir.com/docs/foundry/data-connection/export-overview/#table-exports)。在现有 Data Connections 内只选择一个由部署端预置、独立核验的本地合成接收端。不提供任意地址、自动多发、故障回退或生产连接。原入口仍指向主接收端，旧回执归属不变。
- 审核版本、授权与撤销代次、尝试和目标回执按选定接收端隔离。相同请求不能改接收端或换载荷。接收端响应丢失时，只在同一个已核验接收端找原回执；错连、撤权、凭证版本或身份变更不会转发到另一个端。
- 用两个独立且结构相同的 PostgreSQL 夹具核验真正写入、错误地址、授权隔离、回放与失败路径。界面不显示主机、凭证或验证材料。仅独立隔离环境，不部署。

### 已保存 PostgreSQL 连接的暂停与恢复

- 连接暂停不删除凭据、配置或历史。用精确连接版本确认暂停；连接已经被使用时先等当前有界操作结束，忙时提示重试，不在尚有远程操作时宣称已暂停。暂停成功后，保存连接的测试、目录、身份复核、手工运行和定时运行不会再打开源。
- 恢复会生成新的连接版本，旧连通性结果、身份审核、计划和调度不能自动重新生效。需重新验证、审核并启用定时任务；既有已提交原请求仍只读原回执。暂停策略不因关闭新状态操作开关而绕过。
- 仅管理已保存的 PostgreSQL 连接，不改变其它引擎或独立传入凭据的连接操作。用隔离真实数据库验证双连接、在途操作、过期版本、定时路径以及凭据加密和回执完整性。

### 两张可见表之间的有向引用路径

- 在同一 Lineage 表详情选择第二张已存在的可见表，查找从当前表指向目标的声明或外键路径；顺序与引用类型显式标出。不会把路径、跨表箭头或目标回执当成已发生数据流。
- 两端与每一步在同一只读元数据快照中复核可见性，隐藏表不参与，也不从它转接到其它表。搜索至多四跳，并限制邻居和总访问量；被限制时显示未查全，不把它说成全局无路径，即使找到路径也不夸大最短性。
- 验收真实普通表、同长候选、循环、可选注册表缺失、权限、深度和宽度受限、浏览器选择及结果切换。无业务行读取、全局图自动遍历或生产部署。

### 每日 UTC 时点与上游提交组合

- 对照 [Foundry Trigger types](https://www.palantir.com/docs/foundry/building-pipelines/triggers-reference/#compound-trigger) 的时间与事件 AND。复用现有 Automation；只在指定 UTC 时点且有在此前已观察到的完整上游正数提交条件时运行，不提供只有时间即可触发的分支。
- 后台只在时点前最后五分钟找完整证据，可使用本轮更早时已提交的有效事件。时间窗锁定时保存实际使用的回执和当时审核的计划代次。事务中预写的事件时间不能单独证明它已经按时提交。临近时点但尚未被后台观察到的提交不会冒充已满足；错过时点不补跑，允许短时重投已经封存的原任务。
- 验收完整/不完整条件、实际跨时点的未提交事务、重复派发、绑定撤销和旧事件规则。独立的旧每日调度不与混合触发在同一子计划上并行启用。仅隔离环境，默认关闭。

### 有索引保护的范围分页与取消

- 只有现有合成范围预览可使用游标。游标绑定发起者、筛选、分页上限及物理表和主键索引，精确保留有符号 bigint 边界；后续页用主键大于上页末值，不用 OFFSET。每页都在相同有界条件下重新核对物理身份和 EXPLAIN，再读取；不回退到全表扫描。
- 页面可停止请求并保留已成功的数据。停止等待与后台处理结束是不同事实；服务端收到连接中断时尝试取消，仍有独立的查询时间上限。每页是新的读取，不承诺跨页快照。
- 明确区分已到末尾与达到分页预算。验收大整数、大表、签名和身份过期、索引替换、断开连接后的早停与资源释放。普通 Explorer 和生产查询不变。

### 单条等待中的每日 UTC 同步取消

- 参考 [Foundry Builds](https://www.palantir.com/docs/foundry/data-integration/builds/#cancel-an-individual-job) 的单任务概念。本轮仅在现有 Automation 取消一条尚未取得执行锁的本地每日 UTC 任务，不强行中断写入、不撤回已经发送给消息队列的通知、不暂停下一次调度。
- 取消与执行复核同一计划、任务、代次和时段，并竞争同一行锁；执行已开始或结果未确定时返回忙或不可取消，不伪称已停止。取消后任务历史保存终态和时间；老队列消息不能启动它，不制造源读取、目标提交或资产归属。无可验证写入的取消不算质量失败或恢复。
- 验收取消先赢与执行先赢、历史回执不变、超时、权限、独立下一时段及真实浏览器确认。默认关闭，不部署。

### 两张可见表的共同上游引用

- 参考 [Foundry 血缘展开](https://www.palantir.com/docs/foundry/data-lineage/explore-lineage/) 的共同上游概念。在现有两表选择器查询一张可见上游表，并给出该表指向两个目标的各自引用路径。两条路径都必须有实际声明或外键证据；两个目标自身或只共享下游不算结果。
- 两边在同一只读快照分别搜索最多四跳，按可见性和预算约束，隐藏、停用和保留表都不做中间节点。搜索截断则明确说明未查全，不宣称返回全局最近或证明两表没有共同上游；引用仍不等同真实数据流。
- 验收两条路径、可见性变化、预算、无结果、真实浏览器选择以及普通有向路径兼容性，不查询业务数据、不部署。

### 数据字段时间与同步提交时间的差距

- 参考 [Foundry Data freshness](https://www.palantir.com/docs/foundry/health-checks/checks-reference/#data-freshness)。现有 Quality 在专用合成表上单独审核时间字段、索引和允许时差。分别显示读到的数据时间、已核验写入提交的参考时间和本次检查时间；不把新的提交或页面刷新当作数据更新。测量也不证明字段值来自这一笔同步。
- 仅在有更新且已核验的真实提交时，由现有后台任务核对时间戳索引及查询计划，再最多取一个时间值，不全表扫描或读取其它列。日期无效、无结果、晚于参考提交、索引重建或查询受阻时保守显示未知。旧回执不续延新鲜度；明确的延迟告警只由更新的健康结果恢复。
- 该行为默认关闭，仅在固定合成目标验收；浏览器只读后台已保存结果，不收集业务值，不改变财报或其它资产。

### 比较两次已提交的 Builder 输出

- 参考 [Foundry Time Travel](https://www.palantir.com/docs/foundry/dataset-preview/time-travel/) 的真实版本事实。Builder 历史可选两个已封存结果，先验两份输出、各自已审核配置、来源绑定和当前权限，再读双方存储结果。此操作不会重跑转换、查询活动数据或创建输出。
- 有相同列和顺序、且实际保留有效主键的输出按精确 bigint 主键比较。返回新增、移除、变更和未变更计数，差异内容另有小上限；投影缺少主键或排序不一致时明确不兼容，不能以行号填补。比较结果继续继承双方适用的最严格标记。
- 验收真实已提交版本、空结果、列不兼容、大整数行键、权限拒绝先于读取、封存数据不一致、浏览器切换。仅隔离环境，不部署。

### 已观察到的手工表间传输

- 在现有表级 Lineage 将实际观察与普通声明、外键、路径查询分开。只在本地受控范围、当前授权和近期时间窗内展示。必须同时有正数写入回执、准确的手工路线和当前源表与目标表的物理绑定；仅目标有回执、零行、定时或未知情况不推断这条边。只使用已有的提交事件证据；开启观察不会额外发布可触发调度的事件。
- 按入向或出向展示每个真实表对最近的合格回执；源或目标变更、计划失效、任一端不可见时不再展示为当前观察。历史回执仍从原运行记录读取，不重挂给同名新表。
- 查询只看元数据和不可变运行证据，不读两端业务行。验收真实手工提交、重跑、排除不完整证据、两端重写、权限和显示上限；仅隔离环境，默认关闭，未部署。

### 只追加且冲突整批拒绝的表导出

- 参考 [Foundry 表导出](https://www.palantir.com/docs/foundry/data-connection/exports-table/) 的不同写入模式。保留原 Upsert 为默认；对一个明确审核的合成接收端可单独启用只追加。只插入新主键；若有一个冲突，整个批次回滚，不改已有行、不生成成功回执。
- 模式属于被审核和授权的配置，也是同请求重试的约束，不能在执行时替换。失去确认时只在原接收端按原模式核对确切回执；不能用换模式、换接收端或跳过冲突来假装成功。
- 实测两种模式、已存在主键导致整批失败、历史 Upsert 兼容、授权变更、接收端实提交后恢复。须先统一升级发送端再开启可选模式；旧发送端不能为当前只追加审核写入默认 Upsert 的新授权或请求。只限隔离环境，默认关闭，不部署。

### 普通 Explorer 的筛选索引覆盖提示

- 在现有 Filter 显式检查受支持的条件，只送字段和运算符。后端先确认当前可见表、schema 及参与列的权限，再查 PostgreSQL 目录；不发送筛选值、不生成业务查询、不读业务行、不触发 Apply。
- 支持一个条件或 2–3 个互异列的平铺 AND 条件。只认同一个有效普通 B-tree 的连续查找键前缀：按实际索引顺序，前导键须为等值，最后一个被检查的键可为范围。填写条件的顺序不影响判断。多个独立索引、跳过前导键、INCLUDE、条件索引和表达式索引不算该候选。没有候选不代表一定扫描全表；有候选也不保证规划器会选它。详见 [PostgreSQL 多列索引](https://www.postgresql.org/docs/17/indexes-multicolumn.html)。
- 复杂组合或不同查询形状不会得到误导性的保证。本提示不改变原有筛选的执行，更不替代有执行前保护的合成试点；只在隔离环境验收，不部署。

### 已审核普通表的索引验证 ID 抽样

- 在原筛选之外提供独立的显式抽样，只给部署方审核、栏位权限和物理身份均匹配的当前普通表。部署端需在环回数据库单独预置 `public.ontology_explorer_indexed_sample_identity(marker uuid PRIMARY KEY)` 的一条记录，以及最多三个表与索引的精确物理绑定。首版仅支持单列 bigint 主键等值或范围，最多显示 20 个 ID（额外一个探知是否还有更多），不读其它列或自动应用普通筛选。
- 用预计执行的同一参数化语句验证 PostgreSQL 计划。表或索引身份变化、锁忙、计划包含全表扫描或不支持的节点时明确拒绝，不回退普通查询。精确保留大整数；数据行数量有界，不承诺固定次数的物理 I/O。
- 验收真实大普通表、精确审批列表与权限、索引重建、实际无读行拒绝、取消和现有 Apply 兼容性；默认关闭，只用隔离数据，不部署。

### 两张可见表的共同下游引用

- 复用现有 Lineage 两表选择器，分别沿出向声明或外键查找一个共同可达的可见表，展示从两张输入表到同一目标的两条真实引用路径。共同上游、两端自身或没有有效边不算此结果。
- 两边共用一份只读元数据快照，各最多四跳并有独立预算。隐藏、停用和保留表不作为候选或中间节点，截断只说明未查全。结构上共同可达不等于实际数据流或确定影响。
- 普通路径和共同上游保持原样。验收两分支、同长结果、权限、可选注册表、真实浏览器与取消旧请求；不扫业务数据、不部署。

### 列级声明与外键引用

- 参考 [Foundry Find datasets with a given column](https://www.palantir.com/docs/foundry/data-lineage/find-column/) 的列入口。本系统另外区分真实列映射和按位置配对的外键；不把不同表的同名列或引用方向当作值的流动。
- 在现有 Explorer Schema 选列后定位到同一表级 Lineage。只有当前可见表、真实列、两端均有列读取权限才列出元数据结果；复杂多跳、猜测映射和业务列值不返回。可选声明注册表缺失时仍可查询原生外键。
- 验收真实复合外键的顺序、入向和出向、无权限与不存在同样不可见、隐藏表不占结果配额和真实浏览器；不读取业务行，不部署。

### 运行时间线按日期和结果筛选

- 在现有资产时间线按明确时间范围和结果查看记录。已提交来自持久回执；已拒绝来自已归属的尝试；结果未确认不能视为提交、失败或任务仍运行。未执行的取消仍保留在原 Automation 记录，不伪造资产行。
- 先应用时间和结果约束，再分页；游标属于精确资产和筛选，更换后不能沿用。历史筛选不改（也不伪造）当前正数提交证据。普通未筛选入口保持兼容。
- 验收日期边界、并列键、错配回执、授权、物理重写、浏览器切换及结果迟到。不查询业务行、不部署。

### 有界的最低行数健康检查

- 参考 [Foundry Row count](https://www.palantir.com/docs/foundry/health-checks/checks-reference/#row-count)。本地试点只验证是否至少有已审核的 N 行，并把 N 限制在 1–100；不计算或声称表的精确总数。每次只在更新且确实写入的受控回执后执行。
- 在相同参数和受控物理表、索引下，先核验 PostgreSQL 的有界主键索引计划，再最多取 N 个常量标记；不读或展示主键值及其它数据，不全表计数、不回退。只有有界读取确实提前到末尾才报告不足；不支持计划、锁争用、过期或回执不清楚为未知。
- 沿用现有 Quality 和后台检查；真正不足才开告警，确认只是已读，只有更新的正向核验才恢复。验收上下界、真实无索引拒绝、重复回执、失效配置和浏览器；隔离环境，默认关闭，不部署。

### 从手工传输证据打开原回执

- 已观察数据流旁的链接打开现有目标表 Evidence 时间线中的精确提交回执。出向以对端为目标，入向以当前选定表为目标。即使旧回执不在时间线第一页，也无须用别的记录代替。
- 服务端重新核对授权、两端当前可见性以及手工传输和回执的精确证据，隐藏、缺失、传错目标不可回退到其它表。若任一同名表被替换，旧回执只显示历史范围，不挂到当前实体。切换、退出和错误会清除旧界面结果。
- 不增加面板、数据复制、历史写入或生产部署。

### 封存输出交接的双重授权预检

- 参考 [访问控制传播](https://www.palantir.com/docs/foundry/security/access-control-propagation/) 和 [可导出标记](https://www.palantir.com/docs/foundry/data-connection/export-overview/)。在现有 Builder 封存输出历史核对一次明确的本地合成交接资格。能看输出不意味着经批准可交接；在固定接收方仍需独立授权，接收方的允许标记须覆盖实际输出与全部来源的约束。
- 预检使用精确的封存结果、当前授权和接收方一代审核配置；不降低标记。不合格不产生回执、分发或副作用；合格也只是预检结论，不授权发送。不会读取任何输入或输出行、连接接收方、排队或复制。
- 验收真实封存结果、权限组合、撤销、接收方额度失配、不可变来源和浏览器确认；本地默认关闭，不部署。

### 保留标记的本地私有交接

- 资格预检不授权写入。另行启用执行许可、确认精确封存结果和指定私有接收方之后，才在同一个隔离数据库提交一份副本。复制之前复核所有来源和实际标记以及独立接收方权限；标记原样继承，不可降低，不连接外部接收方。启用前须在隔离库预置独立数据库标记、物理接收端指纹和执行授权；迁移本身不授权写入。
- 已封存的精确有界结果、其原始保护以及独立回执同事务保存。发生故障一起回滚；原请求按授权只找原回执，不重复写入。零行不代表数据流；通用查询和发布不能访问私有副本。

### 已审核的主键区间快照同步

- 在固定合成 PostgreSQL 源和目标上，可在快照计划审核中录入 bigint 主键起止值，含起止两端。手工和现有定时任务都只能用当时的审核版本，运行时不临时覆写区间；这不是增量游标。其它行不改、不删，旧快照和已提交批次模式保持独立。
- 在源事务核对身份、源表和主键索引，检查同一有界范围 SQL 的实际选用计划，再最多试取 101 行。隔离 PostgreSQL 17 的测试角色只在固定源表另获 MAINTAIN 来取得 SHARE 锁，没有业务行写权限；仅有 SELECT 会拒绝，不应给通用或生产连接扩大权限。超过 100 行整批拒绝；索引不符不回退；空范围结果不当成数据移动。
