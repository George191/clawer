# Ontology Foundry：完整验收准备清单

本清单只覆盖 Clawer 仓库内的 Ontology Foundry 本体管理模块。不涉及 Spider、财报或专利迁移。功能基准、官方文档和技术边界见 [FOUNDRY-PARITY.md](./FOUNDRY-PARITY.md)。

**当前判定：11 项均有受限实现，0/11 达到完整验收。** 隔离 PostgreSQL、自动化任务和 Chromium 的通过记录证明下表中的特定路径，不证明生产可用、全部连接器等价或完整复制 Palantir。

此前的隔离回归中，应用及任务 322 项通过、37 项因未配置各自的测试环境而跳过；独立迁移和可见性测试 13 项通过。

2026-11-18 在指定主机 20.22 完成发布前盘点。通过正常登录读取到一个内置仓库、53 个可见物理对象；其中 RDS 24 个、ODS 28 个、TASK 1 个。代表性 ODS 表的列目录、预览策略和声明关系可读。采样时已有外部连接、已发布语义类型、批同步计划和传输计划均为零。CDC 诊断显示 PostgreSQL 可用，Kafka Connect 未配置，Kafka 和 MongoDB 探针不可用。通用业务链路的外部源、增量交付、目的端和 SLA 仍需逐项验收。

语义项目沿用每团队一个项目权限范围。平台管理员通过组织管理创建组织及团队时成为新团队的 OWNER；在本体向导选定该团队后，可设置独立的项目名。项目负责人由提交命名的有效管理成员担任，已有定义和权限继续使用同一项目 ID。此流程的登录、组织、团队、项目命名、发布、动作和撤权回归见 `app/web/tests/test_ontology_published_workflow.py`。

| 1. 数据源与连接器 | PostgreSQL 独立源身份、可见目录、暂停恢复和凭证更换时的版本保护。 | 指定实际要上线的连接器及测试实例；逐个验证网络/TLS、最小权限、凭证轮换和撤销。驱动可导入不算通过。 |
| 2. 批量同步 | 同步版本、快照、受限增量、可追溯回执，以及不写目标的下一批核验。 | 指定代表性测试源/目标、真实变更和检查点语义；验证足量批次、失败回滚、延迟、重试和调度。 |
| 3. 推送与 CDC | 两个合成签名生产者、暂停、接收去重、已接收事件与原应用回执核对。 | 指定测试生产者及已批准的入口或 Kafka/WAL 环境；核准 schema 演进、删除事件、偏移、重放、限流与轮换。 |
| 4. 对外推送与写回 | 固定隔离接收端的冻结、单次投递和只读回执检查；响应丢失不重发。 | 指定并批准非生产的真实测试目的端、字段、写入策略与保留规则；在该环境验证回执、权限撤销和恢复。 |
| 5. 通道与调度 | 既有 Automation 中的每日、每周及受限每月 UTC，以及部分上游条件。 | 指定代表性数据链路和实际所需时点、时区、补跑与取消规则；验收运行预算、并发和作业代次。 |
| 6. 血缘与影响 | 有界表级路径、已声明的列级映射链、受限的提交证据及历史区分。 | 提供真实测试管道的映射及执行证据，验证跨源/变换/结果的权限、身份与影响，不把结构声明当成数据移动。 |
| 7. 运行历史 | 同一资产的提交和尝试时间线；核对已提交月度任务的原端点和回执。 | 覆盖目标实际会使用的手工、计划、推送等运行类型；确认留存期、分页、角色可见性及丢失确认处理。 |
| 8. 数据集查看 | 指定表不走普通预览回退；只用经核实的覆盖索引返回最多 20 行审核字段；另外验证了有界取消和存量统计。 | 指定一张代表性大表、允许结果字段及物理索引；按实际更新强度测量预算、超时和查询体验。仅返回少量字段并不保证不访问堆页。 |
| 9. 质量与新鲜度 | 实际后台评估、Schema 差异、有限行数/大小检查、站内告警与确认。 | 指定真实适用的基线、时间字段及阈值，验收误报、滞后和恢复；对外告警目的端另行授权。 |
| 10. 可视管道与版本 | 固定合成输入转换、不可变配置与输出、对比、保留标记的历史配置恢复。 | 提供代表性测试图、输出与变更方式；按实际版本留存、回滚和授权验证端到端结果。 |
| 11. 权限与标记 | 严格区分技术连通、预检、交接写入、原发送方和接收方只读证明。 | 核准测试角色/标记矩阵、获准资产和接收方，验证租户隔离、权限撤销、端到端传播与审计。 |

## 最短下一步

1. 先确定能通过发布检查的 Git 路径，核对远程分支、待发布变更和准确的提交树。没有验证发布不等于代码没做；发布也不等于部署或验收。
2. 指定一个获准的非生产环境，确认哪些测试资产可用，以及谁可批准部署和迁移。通过已批准的凭证管理方式配置最小权限，不在消息中传密码、令牌或完整连接串。
3. 第一轮先用 **一对 PostgreSQL 测试源和目标、一张有代表性的大表、一个标记保护的测试输出及不同测试角色**。它可覆盖核心数据链路；其他真实连接器、CDC、任意目的端按实际业务逐一单列，不用替代测试宣布通过。

每行关闭前至少保留：测试版本、授权和物理范围、成功结果、拒绝/撤权结果、失败恢复、运行预期。隔离夹具、模拟消息通道或截图不能代替真实非生产环境的相应证据。
