# 财报信息库表定义 V1.0

## 1. 文档说明

本文整理当前 SEC/EDGAR 财报数据的库表设计。

### 1.1 设计范围

- 数据来源：SEC EDGAR，包括公司主数据、申报记录、申报文件索引和 Company Facts。
- 当前实际持久化：MongoDB 中的 `sec_edgar_company`、`sec_edgar_filing` 及 Company Facts 记录。
- ODS 目标表：建议新增 PostgreSQL 财报 ODS 表组，作为下游清洗、检索和 DWD 加工的统一明细层。
- 设计原则：原始数据保留，标准字段可检索；同一公司、同一报告期、同一指标允许存在多个申报版本，但必须保留 accession 号和修订信息。

## 3. 当前数据对象

### 3.1 ODS 公司主表：`ts_ods.ods_company`

保存 CIK、公司名称、交易所和证券代码等主体信息，是 ODS 财报数据的公司维度；SEC 返回字段仅作为该 ODS 表的数据来源。

#### 字段定义

| 序号 | 中文名 | 字段名 | 类型 | 必填 | 示例 | 说明 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | CIK | `cik` | String | Y | 0000320193 | SEC 公司唯一标识，统一补齐 10 位；公司主键 |
| 2 | 公司名称 | `name` | String | Y | Apple Inc. | SEC 注册主体名称；不可仅凭名称判断公司是否相同 |
| 3 | 实体类型 | `entity_type` | String | N | other | 申报主体业务类型 |
| 4 | 交易所 | `exchanges` | Array[String] | N | `["Nasdaq"]` | 上市交易所；非上市主体可能为空 |
| 5 | 证券代码 | `tickers` | Array[String] | N | `["AAPL"]` | 公司对应的 ticker 列表 |
| 6 | 分类代码 | `sic` | String | N | 3571 | SEC Standard Industrial Classification 代码 |
| 7 | 行业描述 | `sic_description` | String | N | Electronic Computers | SIC 对应行业描述 |
| 8 | 公司地址 | `address` | JSONB | N | `{"city":"Cupertino"}` | SEC 返回的地址对象；可包含州、国家、邮编 |
| 9 | 官网 | `website` | String | N | https://www.apple.com | SEC 或公司资料中的官网地址 |
| 10 | 数据来源 | `data_source` | String | Y | sec_edgar | 固定标识数据来源 |
| 11 | 记录创建时间 | `created_at` | ISODate | N | 2026-09-09T10:00:00Z | 首次入库时间 |
| 12 | 记录更新时间 | `updated_at` | ISODate | N | 2026-09-09T10:00:00Z | 最近更新时间 |
| 13 | 数据类型 | `data_type` | String | N | company | 数据类型 |
| 14 | 记录标识 | `record_id` | String | Y | 63957abd038fbc723050f28e26a2437 | 唯一标识 |

#### ODS 主键与索引

- 主键：`cik`。
- 索引：`tickers`、`name`、`exchange`、`updated_at DESC`。
- 财报事实、申报记录均通过 `cik` 关联公司主表；名称仅用于展示和候选匹配。

#### 示例

```json
{
  "record_id": "63957abd038fbc723050f28e26a2437",
  "cik": "0000320193",
  "name": "Apple Inc.",
  "entity_type": "other",
  "exchanges": ["Nasdaq"],
  "tickers": ["AAPL"],
  "sic": "3571",
  "sic_description": "Electronic Computers",
  "address": {
    "street1": "ONE APPLE PARK WAY",
    "city": "CUPERTINO",
    "state": "CA",
    "zip": "95014",
    "country": "US"
  },
  "website": "https://www.apple.com",
  "data_source": "sec_edgar",
  "data_type": "company",
  "created_at": "2026-09-09T10:00:00Z",
  "updated_at": "2026-09-09T10:00:00Z"
}
```

### 3.2 ODS 申报表：`ts_ods.ods_filing`

保存 accession number、表单类型、报告期、申报日期、文件索引地址及索引解析状态。申报记录是 ODS 财务事实的来源锚点。

### 3.3 ODS 财务事实来源映射

SEC Company Facts 的 `entityName` 和 `facts` 解析后写入 `ts_ods.ods_financial_fact`；`facts` 按 taxonomy（如 `us-gaap`）、概念名称、单位和事实数组组织，每个事实包含 `fy`、`fp`、`form`、`filed`、`frame`、`val`、`accn`、`start`、`end` 等信息。

## 4. 标准 ODS 表组设计

采用 4 张表，分别承担主体、申报、原始文件和财务事实职责：

| 表名 | 层次 | 粒度 | 作用 |
| --- | --- | --- | --- |
| `ts_ods.ods_company` | ODS | 一家公司一个 CIK | 公司主体与证券标识 |
| `ts_ods.ods_financial_filing` | ODS | 一次 SEC 申报一个 accession | 申报、报告期、文件索引和采集状态 |
| `ts_ods.ods_financial_document` | ODS | 一个申报文件一个文件记录 | 原始 HTML/XBRL/PDF 文件及对象存储定位 |
| `ts_ods.ods_financial_fact` | ODS | 一个申报中的一个概念、单位、期间事实 | 标准化财务指标明细 |

其中，`ods_financial_fact` 是财务分析的核心明细表；`ods_financial_report` 可作为兼容视图或旧名称，不再作为唯一物理表名。

### 4.1 表间关系

```text
ods_financial_company (cik)
             1 ────── N
ods_financial_filing (filing_id / accession_number)
             1 ────── N
ods_financial_document
             1 ────── N
ods_financial_fact
```

所有表均保留 `data_source`、`data_type`、`created_at`、`updated_at`；事实表通过 `cik + accession_number` 追溯公司和申报，不通过公司名称关联。

### 4.2 `ts_ods.ods_company` 字段口径

字段定义以 ODS 物理表为准，本文第 3.1 节仅说明来源和业务含义；物理表使用 `record_id + data_source + data_type` 作为分区兼容主键，`cik` 作为 SEC 业务键。

### 4.5 `ts_ods.ods_financial_fact` 字段定义

| 序号 | 中文名 | 字段名 | 类型 | 必填 | 示例 | 说明 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 记录ID | `record_id` | String | Y | sec_10k_0000320193_20241231_revenue | 记录稳定主键；建议由 CIK、概念、报告期、单位和 accession 计算 |

| 8 | 申报日期 | `filed_date` | Date | Y | 2025-01-31 | SEC filed 日期 |

| 10 | 报告期结束 | `period_end` | Date | Y | 2024-12-31 | 事实的 end |
| 11 | 财政年度 | `fiscal_year` | Integer | N | 2024 | Company Facts 的 fy |
| 12 | 财政期间 | `fiscal_period` | String | N | FY | 如 FY、Q1、Q2、Q3 |
| 13 | 报告窗口 | `frame` | String | N | CY2024 | SEC frame；没有时为空 |
| 14 | Taxonomy | `taxonomy` | String | Y | us-gaap | 如 us-gaap、dei、ifrs-full |
| 15 | 财务概念 | `concept` | String | Y | RevenueFromContractWithCustomerExcludingAssessedTax | taxonomy 下的概念名 |

| 20 | 修订标记 | `is_amendment` | Boolean | Y | false | 表单以 /A 结尾时为 true |
| 21 | 来源文件URL | `filing_url` | String | N | https://www.sec.gov/Archives/... | 申报文件或 filing index 地址 |
| 22 | 记录创建时间 | `created_at` | ISODate | N | 2026-09-09T10:00:00Z | 入库时间 |
| 23 | 记录更新时间 | `updated_at` | ISODate | N | 2026-09-09T10:00:00Z | 最近更新时间 |

### 4.6 财务事实表主键与索引

- 逻辑唯一键：`(record_id, data_source, data_type)`。
- 唯一业务键：`(cik, accession_number, taxonomy, concept, unit, period_end, value)`；同一申报中的重复事实应在清洗阶段去重。

### 5.4 关联说明

- `ods_financial_company.record_id`：建议使用 CIK，例如 `0000320193`。
- `ods_financial_filing.record_id`：建议使用 accession number，例如 `0000320193-25-000079`。
- `ods_financial_document.record_id`：建议使用 accession number 加文件名生成。
- `ods_financial_fact.record_id`：必须保证同一申报、概念、单位、报告期和数值组合下稳定且唯一。
