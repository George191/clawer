# 智能采集工作台合并方案 — 三页合一

> 状态: 待三方评审

---

## 1. 背景与决策

### 1.1 当前问题

当前 AI 智能采集线拆分为三个独立页面：

| 页面 | 路由 | 文件大小 | 核心职责 |
|------|------|----------|----------|
| AI 智能采集 | `/ai-collect` | ~28KB | 自然语言→页面分析→字段合约→试跑→发布 |
| 模板库 | `/templates` | ~12KB | 模板资产管理（卡片网格 + 状态 + 版本） |
| 采集任务 | `/tasks` | ~18KB | 任务调度看板（分组 + 状态 + 子任务 + Drawer） |

**问题**：
1. 用户完成 AI 采集发布后，需要手动跳转到模板库查看资产、再跳到任务中心查看运行——割裂的体验
2. 三个页面各自独立的状态管理，无法实现"模板→任务→运行"的连贯交互
3. 系统感不足：像三个独立工具拼凑，而非一个统一的采集工作台

### 1.2 合并决策

**将三个页面合并为单一「智能采集工作台」页面**，所有功能通过交互触发，不离开当前页面。

## 2. 产品维度 — 供产品经理评审

### 2.1 合并后的页面定位

**智能采集工作台** 是数据中台 DataHub 的核心操作入口，覆盖从"想法→采集→资产→运行→监控"的完整链路。

### 2.2 功能区域映射

| 原页面 | 原功能 | 合并后位置 | 交互方式 |
|--------|--------|-----------|----------|
| AI 采集 | 自然语言输入 + 页面分析 + 字段合约 + 试跑 + 发布 | **左侧栏 → 新建采集** 按钮触发全屏向导 | 模态向导（Wizard）覆盖在工作台上 |
| AI 采集 | 实时分析过程（6 步流程 + 终端日志 + 上下文） | 向导内嵌的实时面板 | 向导内三栏布局 |
| 模板库 | 模板卡片网格 + 搜索 + 状态筛选 | **主区域 → 模板视图** | 卡片/列表切换 |
| 模板库 | 新建模板 | **左侧栏 → 新建模板** 按钮 | 模态表单 |
| 任务中心 | 任务看板 + 分组 + 状态 + 子任务 | **主区域 → 任务视图** | 看板/列表切换 |
| 任务中心 | 任务详情 Drawer | 右侧滑出 Drawer | 不变 |
| 三者通用 | 从模板创建任务 | 模板卡片 → 右键/更多 → 创建任务 | 确认弹窗 |

### 2.3 需产品经理确认的事项

1. **默认落地视图**：进入工作台后默认展示"模板视图"还是"任务视图"？  
   建议: 任务视图（用户更关心运行状态）

2. **AI 新建采集向导的关闭行为**：用户中途关闭向导，是否保存草稿？  
   建议: 保存到左侧栏"草稿"区域，下次可恢复

3. **模板→任务的转化路径**：从模板创建任务时，是模态弹窗还是跳转到向导？  
   建议: 模态弹窗（轻量），仅当需要高级配置时才打开向导

4. **视图切换时筛选状态保持**：切到任务视图再切回模板视图，筛选条件是否保留？  
   建议: 保留，用户会频繁切换对比

5. **模板卡片/列表双视图**：是否需要列表视图？  
   建议: 保留卡片视图为主，列表视图作为紧凑模式

6. **任务看板的分组维度**：当前按 prototype/beta/launch 分组，是否增加按模板分组？  
   建议: 增加分组维度切换（按阶段 / 按模板 / 按状态）

### 3.2 左侧导航栏设计

| 图标 | 含义 | 对应原页面 |
|------|------|-----------|
| 🤖 | 新建采集 | AI 采集入口 |
| 📋 | 模板资产 | 模板库 |
| ⚡ | 任务运行 | 任务中心 |
| 📊 | 运行监控 | 监控页快捷入口 |
| 📁 | 草稿箱 | AI 采集中途保存的草稿 |

- 宽度: 52px（与全局 MainLayout 一致）
- 激活态: accent 色左边框 + 背景色变化
- 底部: "+ 新建" 按钮，触发 AI 采集向导

### 3.3 主区域视图切换

#### 模板视图（模板库增强）

- 顶部工具栏: 搜索框 + 状态筛选 + 卡片/列表切换 + 排序
- 内容: 模板卡片网格（3列，与现有 Templates 一致）
- 卡片增强: 
  - 右下角增加"关联任务"数量徽章
  - 点击卡片 → 右侧 Drawer 展示模板详情 + 关联任务列表
  - 卡片右键/更多菜单 → "创建任务" / "试跑" / "停用" / "复制"

#### 任务视图（任务中心增强）

- 顶部工具栏: 搜索框 + 状态筛选 + 分组维度切换 + 看板/列表切换
- 内容: 任务看板（与现有 TaskCenter 一致）
- 增强交互:
  - 任务行点击 → 右侧 Drawer（不变）
  - 任务行新增"关联模板"列，可点击跳转到模板视图
  - 底部状态栏: 运行/失败/队列数实时统计

### 3.4 AI 采集向导（全屏覆盖层）

**触发**: 左侧栏"+ 新建"按钮 或 模板卡片"新建采集"

**布局**: 全屏覆盖层（z-index 高于工作台），内嵌三栏：

```
┌─────────────────────────────────────────────────────────┐
│  ← 返回工作台           AI 智能采集向导         [✕ 关闭]   │
├──────────┬──────────────────────────┬───────────────────┤
│          │                          │                   │
│ 步骤导航  │    主工作区               │   AI 上下文 +      │
│ (6步)    │    (投射/合约/试跑/发布)   │   实时日志         │
│          │                          │                   │
│  ① 准备   │   [当前步骤的内容]         │   [终端日志流]     │
│  ② 入口   │                          │                   │
│  ③ 结构   │                          │   [AI 上下文卡片]   │
│  ④ 合约   │                          │                   │
│  ⑤ 试跑   │                          │                   │
│  ⑥ 发布   │                          │                   │
│          │                          │                   │
└──────────┴──────────────────────────┴───────────────────┘
```

- 向导复用现有 AICollect 的全部逻辑（6 步流程、SSE、字段合约、试跑、发布）
- 发布成功后 → 关闭向导 → 工作台自动切到模板视图 → 新模板高亮提示
- 向导可随时最小化到左侧栏"草稿箱"

### 3.5 需 UI/UX 确认的事项

1. **左侧栏图标体系**：建议统一用线性图标（与 MainLayout 一致），还是允许用 emoji？  
   建议: 线性图标，与全局设计系统一致

2. **视图切换动画**：模板↔任务视图切换是否需要过渡动画？  
   建议: 淡入淡出 200ms，避免页面跳动

3. **AI 向导的覆盖方式**：全屏覆盖还是嵌入式（工作台内切换）？  
   建议: 全屏覆盖层，保持工作台上下文不被打断

4. **模板卡片的"关联任务"展示**：徽章数字还是缩略列表？  
   建议: 徽章数字（≥3 时显示 3+），hover 时展开缩略列表

5. **暗色色板**：继续使用 aura 色板（#15191F 底）还是调整？  
   建议: 统一使用 aura 色板，accent 色用 cyan (#8FE3E8)

6. **底部状态栏**：是否需要常驻底部状态栏？  
   建议: 需要，显示运行/失败/队列数 + 快捷跳转监控页

## 4. 技术维度 — 架构设计

### 4.1 路由变更

```typescript
// App.tsx 变更
// 旧:
//   /ai-collect     → AICollect
//   /templates      → Templates
//   /tasks          → TaskCenter

// 新:
//   /collect        → CollectConsole（合并后单页面）
//   /collect/new    → AI 采集向导（也可作为覆盖层内嵌）
//   /collect/:tab   → 指定初始视图（templates / tasks）
```

- 旧路由保留 301 重定向到 `/collect`
- `/ai-collect` → `/collect?action=new`
- `/templates` → `/collect?tab=templates`
- `/tasks` → `/collect?tab=tasks`

### 4.2 组件结构

```
src/pages/CollectConsole/
├── index.tsx                    # 主页面容器（布局 + 左侧栏 + 视图切换）
├── Sidebar.tsx                  # 左侧导航栏
├── TemplateView.tsx             # 模板视图（从 Templates 迁移增强）
├── TaskView.tsx                 # 任务视图（从 TaskCenter 迁移增强）
├── CollectWizard.tsx            # AI 采集向导覆盖层（从 AICollect 迁移）
├── TaskDetailDrawer.tsx         # 任务详情抽屉（从 TaskCenter 抽取）
├── TemplateDetailDrawer.tsx     # 模板详情抽屉（新增）
├── CreateTaskModal.tsx          # 从模板创建任务弹窗（新增）

└── shared/
    ├── aura.ts                  # 统一色板（提取到共享文件）
    ├── types.ts                 # 共享类型定义
    └── mockData.ts              # Mock 数据集中管理
```

### 4.3 状态管理

```typescript
interface CollectConsoleState {
  activeTab: "templates" | "tasks";        // 当前视图
  activeGroup: "prototype" | "beta" | "launch" | "template" | "status"; // 任务分组维度
  wizardOpen: boolean;                      // AI 向导是否打开
  wizardMinimized: boolean;                 // 向导是否最小化到草稿箱
  selectedTemplate: string | null;          // 选中的模板（用于 Drawer）
  selectedTask: string | null;              // 选中的任务（用于 Drawer）
  templateFilter: { keyword: string; status: string };
  taskFilter: { keyword: string; status: string };
  statusBar: { running: number; failed: number; queued: number };
}
```

### 4.5 与现有组件的兼容

- `MainLayout`：无需修改，`/collect` 路由内嵌即可
- `ErrorBoundary`：每个子组件独立包裹
- `aura` 色板：提取到 `shared/aura.ts`，所有子组件共享
- Mock 数据：集中到 `shared/mockData.ts`，方便后续替换为 API

## 5. 实施计划

### 5.1 分步执行

| 步骤 | 内容 | 预计工作量 |
|------|------|-----------|
| S1 | 创建 CollectConsole 目录结构 + 提取共享文件 | 0.5h |
| S2 | 实现 index.tsx 主容器 + Sidebar + 视图切换 | 1h |
| S3 | 迁移 Templates → TemplateView（增强关联任务徽章） | 1h |
| S4 | 迁移 TaskCenter → TaskView（增强分组维度切换） | 1h |
| S5 | 迁移 AICollect → CollectWizard（适配覆盖层） | 1h |
| S6 | 新增 TaskDetailDrawer + TemplateDetailDrawer + CreateTaskModal | 1h |
| S7 | 新增 StatusBar + 视图联动 | 0.5h |
| S8 | 路由变更 + 旧路由重定向 + 编译验证 | 0.5h |
| S9 | 交互打磨（动画、hover、空状态） | 0.5h |
| **合计** | | **~7h** |

### 5.2 风险点

1. **AICollect 迁移风险**：AICollect 有 SSE 流式分析和复杂的状态机，迁移时需确保所有逻辑完整保留
2. **状态联动**：模板视图和任务视图需要共享数据（模板→关联任务），需设计好状态管理
3. **路由兼容**：外部链接可能引用旧路由，需保留重定向

## 7. 结论

三页合一不是简单的代码合并，而是产品体验的重新设计。核心原则：

1. **系统感**：一个工作台，不是三个工具
2. **交互驱动**：所有功能通过交互触发，不离开当前页面
3. **渐进增强**：保留所有现有功能，在此基础上增加联动
4. **向导隔离**：AI 采集作为向导覆盖层，不打断工作台上下文

等待三方评审反馈后，立即启动实施。
