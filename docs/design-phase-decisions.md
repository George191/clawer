## 一、技术负责人直接决策事项（无需确认）

以下事项属于技术架构范畴，技术负责人直接拍板：

### D1: 监控页增强方向

**决策**: 实时监控页 `/monitor` 增强为 Grafana 风格的面板式布局

**具体方案**:
- 顶部 KPI 卡片保留（成功率/P95延迟/告警数/容量），增加 Mini 折线图（sparkline）
- 新增"采集源站实时状态网格"：6×N 网格，每个源站一个状态块（绿/黄/红 + 当前 QPS）
- 告警时间线增强：分级展示（P0/P1/P2）+ 噪音抑制开关
- 数据流吞吐曲线：面积图，展示最近 1h 各层（RDS→ODS→DWD→DWS→ADS）的 records/s
- **WebSocket 实时推送**: 是。复用现有 `useWebSocket` hook，推送指标更新和告警事件

**理由**: 监控页的核心价值是"实时感知"，Grafana 风格的面板布局是行业最佳实践，WebSocket 推送避免轮询开销。

### D2: 日志追踪增强方向

**决策**: 日志追踪页 `/logs` 增强为终端风格 + Trace 链路可视化

**具体方案**:
- **终端风格日志流**: 暗色背景 + 等宽字体（Fira Code）+ 自动滚动 + 语法高亮（INFO 蓝/WARN 黄/ERROR 红）
- **Trace 链路瀑布图**: 点击某条日志，右侧面板展示同一 traceId 的所有日志按时间排列的瀑布图
- **日志上下文关联**: 点击展开同一 trace 的前后 5 条日志
- **实时日志流模式**: 支持"跟随"模式（类似 `tail -f`），新日志自动滚动到底部

**理由**: 采集链路问题的核心排查方式是 trace 追踪，终端风格是开发者最熟悉的日志阅读方式。

### D3: 页面代码风格规范

**决策**: 所有增强/新增页面严格遵循已有高保真页面的代码风格

**规范要点**:
1. **暗色优先**: 使用 `aura` 色板（参考 TaskCenter/Templates），不依赖 Ant Design token 做暗色适配
2. **内联 style**: CSS-in-JS，不使用 CSS 文件（与现有代码一致）
3. **ErrorBoundary 包裹**: 每个页面根组件用 `<ErrorBoundary>` 包裹
4. **Mock 数据内嵌**: 数据以 const 数组定义在组件文件顶部，便于产品经理和 UI/UX 直接预览
5. **组件结构**: 单文件 `index.tsx`，复杂子组件拆分到同目录下独立文件
6. **不使用 PageHeader 组件**: CommandCenter/AICollect 均未使用，高保真页面自定义标题区域
7. **配色体系**:
   - AI 智能采集线: aura 色板（`#15191F` / `#1F2429` / `#8FE3E8` / `#8B5CF6`）
   - 数据湖线: 深绿系暗色（`#0D1B14` / `#13261C` / `#10B981`），与 accent `#059669` 对齐
   - ETL 管道线: 深蓝系暗色（`#0C1620` / `#122030` / `#0EA5E9`），与 accent `#0EA5E9` 对齐

### D4: 设计执行顺序

**决策**: 严格按产品设计文档的模块优先级执行

### D5: 协作工作流

**决策**: 每个页面按以下流程推进

```
1. 技术负责人产出高保真 React 代码（含 Mock 数据 + 完整交互）
2. 代码提交到 feature 分支，部署到 Staging
3. 三方并行审核:
   - @产品经理-小欣: 审核产品逻辑（功能范围、用户流程、信息优先级）
   - @UI/UX设计师: 审核视觉规范（配色、间距、字号、组件选型、动效）
   - 技术负责人: 代码质量自查（Token 对齐、路由注册、类型安全）
4. 反馈汇总 → 技术负责人迭代修改
5. 三方确认通过 → 合并 main，进入下一个页面
```

**每个页面的审核周期**: 代码产出后 48h 内完成三方审核。

## 二、需要 @产品经理-小欣 确认的事项

以下事项涉及产品逻辑，需要产品经理确认：

### Q1: 监控页指标范围

**当前状态**: 监控页已有 4 个 KPI（采集成功率、P95延迟、活跃告警、运行容量）+ 4 个指标行（成功率、P95延迟、字段缺失率、代理池可用率）

**问题**: 增强后是否需要增加以下指标？
- [ ] 各数据源类型的实时吞吐（爬虫/API/文件/DB同步各自的 records/min）
- [ ] DAG 任务执行概览（今日已执行/运行中/排队/失败）
- [ ] 存储层各层记录数（RDS/ODS/DWD/DWS/ADS 各自总量 + 今日增量）
- [ ] Kafka 消费延迟（各 topic 的 lag）

**技术建议**: 全部加入。这些指标在产品设计文档 M14（监控告警）中都有定义，提前到监控页展示有利于数据中台运维。但展示方式建议为可折叠面板，默认只展开"采集概览"。

### Q2: 日志追踪页的服务范围

**当前状态**: 日志页已有 ai-agent / quality-gate / identity-pool / writer-ods 4 个服务的 Mock 日志

**问题**: 增强后应覆盖哪些服务的日志？
- [ ] 采集层：crawler / engine / adapters / downloader
- [ ] 同步层：syncer / writer-rds / writer-ods
- [ ] ETL 层：etl-ods / etl-dwd / etl-dws / etl-ads
- [ ] 治理层：quality-engine / metadata-collector / lineage-parser
- [ ] 调度层：scheduler / dag-engine
- [ ] 服务层：api-gateway / api-cache

**技术建议**: 按"产品线 → 服务分组"组织，默认展示 AI 采集线的服务日志，支持切换到其他产品线。这比一次性展示所有服务日志更合理。

### Q3: 数据湖产品线页面的产品逻辑优先级

**问题**: 第二批 8 个数据湖页面，是否有产品逻辑上的优先级调整？

**当前设计顺序**: 数据目录 → 分层浏览 → 元数据 → 数据质量 → 血缘关系 → 权限审计 → 数据 API → 指标集市

**技术建议**: 维持当前顺序。理由：
1. 数据目录是入口（用户最先看到）
2. 分层浏览是核心操作（用户最常用）
3. 元数据是治理基础（后续质量/血缘依赖）
4. 质量/血缘是治理深度
5. 权限审计是安全合规
6. 数据 API/指标集市是服务输出

### Q4: 用户角色与权限

**问题**: 高保真原型中是否需要体现多角色视角？

**当前理解**: MVP 阶段单角色（管理员），P2 阶段才有 RBAC

**技术建议**: 原型中不体现多角色，但权限审计页的设计预留角色切换 UI（灰显状态），为 P2 阶段做准备。

## 三、需要 @UI/UX设计师 确认的事项

以下事项涉及视觉规范，需要 UI/UX 确认：

### Q5: 数据湖产品线的暗色色板

**当前方案**: 每个产品线有独立 accent 色，但暗色背景色板需要确认

**技术方案**:
```
AI 智能采集线（已确定）:
  bg: #15191F / surface: #1F2429 / accent: #7C3AED / glow: #8FE3E8

数据湖线（待确认）:
  方案 A: bg: #0D1B14 / surface: #13261C / accent: #059669  (深绿系，与 accent 同色系)
  方案 B: bg: #121A1F / surface: #1A2329 / accent: #059669  (延续 AI 线的中性暗灰，仅 accent 区分)
  方案 C: bg: #0A1620 / surface: #112030 / accent: #059669  (深蓝绿系)

ETL 管道线（待确认）:
  方案 A: bg: #0C1620 / surface: #122030 / accent: #0EA5E9  (深蓝系)
  方案 B: bg: #121A1F / surface: #1A2329 / accent: #0EA5E9  (延续中性暗灰)
```

**技术建议**: 方案 B（统一中性暗灰底色，仅用 accent 色区分产品线）。理由：
1. 用户在不同产品线间切换时，背景色剧烈变化会带来视觉跳跃
2. Neo4j Aura Console 的做法是统一暗色底 + 不同 accent 色
3. 已完成的 TaskCenter/Templates 已经在使用 `#15191F` 底色

### Q6: 图表可视化库选择

**当前状态**: 项目未引入图表库

**需要确认**: 数据湖产品线涉及大量数据可视化（血缘图、质量趋势、指标看板等），需要选择图表库

**技术方案**:
| 方案 | 适用场景 | 包大小 | 推荐 |
|------|---------|--------|------|
| @ant-design/charts | 通用图表（折线/柱状/饼图） | 中 | ✅ 与 Ant Design 生态一致 |
| @antv/g6 | 血缘图/关系图 | 大 | ✅ 血缘关系页必需 |
| recharts | 轻量图表 | 小 | 备选 |

**技术建议**: 
- 通用图表用 `@ant-design/charts`（与现有技术栈一致）
- 血缘关系图用 `@antv/g6`（专业关系图引擎）
- 不引入 recharts（避免多图表库共存）

### Q7: 动效规范

**当前状态**: 已有扫描线动画、脉冲指示器、步骤展开/收起过渡

**需要确认**: 数据湖和 ETL 产品线是否需要新的动效？

**技术建议**:
- 数据目录: 卡片入场 stagger 动画（错落出现）
- 血缘关系: 节点展开/收起的力导向动画
- 数据质量: 规则检查时的进度环动画
- ETL 管道画布: 连接线流动动画（表示数据流向）
- 其余页面: 沿用已有动效规范，不新增
